# Dark.Talk Desktop (Windows)

Десктопная версия Android-мессенджера Dark.Talk: Electron + TypeScript.
Тот же бэкенд (vsp210.ru по умолчанию), тот же HTTP API и WebSocket-протокол.

## Возможности (как в Android 1.1.0)
Вход / регистрация / 2FA, список чатов (фильтры, поиск, непрочитанные, уведомления), личные и групповые чаты,
сообщения в реальном времени по WebSocket (ответы, правка, удаление, реакции, галочки прочтения, «печатает»),
фото, файлы, голосовые (скорость 1x / 1.5x / 2x), настройки (профиль, безопасность/устройства, сеть, 6 тем,
быстрые реакции, кэш), ru/en, интерфейс «жидкое стекло».
**Dark.Call**: аудио- и видеозвонки и показ экрана (WebRTC, P2P), входящий звонок, системные плашки звонков в чате.

## Офлайн-хранилище (как Room в Android)
- Профиль, список чатов с последними сообщениями и **последние 50 сообщений каждого чата** сохраняются в
  `data-cache.json` (профиль приложения). Чаты открываются мгновенно из хранилища, затем обновляются с сервера;
  без сети всё читается из сохранённого. Хранилище обновляется и по событиям WebSocket для всех чатов.
- Скачанные медиа (фото, голосовые, файлы до 64 МБ) лежат в `media-cache/` с лимитом (настройки → Память,
  по умолчанию 500 МБ, вытесняются самые старые).
- Данные принадлежат одному аккаунту: при выходе, смене сервера или другом аккаунте всё удаляется.

## Архитектура
- `src/main` — HTTP (fetch) и WebSocket (`ws`) идут через главный процесс (заголовок `Authorization: Token ...`
  уходит только на ваш сервер). Токен хранится через `safeStorage` (DPAPI). Секретного ключа приложения больше нет.
- `/ws/chats/` — события всех чатов и сигналинг звонков (`call_*`), `/ws/chat/{id}/` — открытая комната
  (отправка сообщений, «печатает»). Опроса нет: после переподключения сокета список и комната синхронизируются один раз.
- `src/renderer/call.ts` — клиент Dark.Call (порт Android `CallManager`): offer/answer/ICE через сокет, TURN берётся с
  `/call/api/ice-servers/`, `call_ping` каждые 8 с, ICE restart, показ экрана через `desktopCapturer`.
- `src/preload` — безопасный мост `window.dt`.
- `src/renderer` — UI на чистом TS. Медиа с авторизацией отдаются через протокол `dtmedia://`.

## Важно
- Звонки требуют обновлённого бэкенда (приложение `call`) и настроенного TURN (см. `call/CALLS.md` бэкенда).
- Только личные чаты (групповые звонки не поддерживаются, как и в Android).
- Голосовые пишутся как webm/opus (Android шлёт m4a). Если сервер не принимает webm — потребуется конвертация.
- .exe не собирался и не запускался в настоящем Electron/Windows: проверены типы и сборка бандла.

## Групповые звонки (1.3.0)

В групповых чатах в шапке появились кнопки аудио- и видеозвонка. Звонок идёт по схеме mesh: каждый участник напрямую
соединяется с каждым (WebRTC), сервер только пересылает сигналинг. Поэтому участников ограничено (по умолчанию 6,
`CALL_GROUP_MAX_PARTICIPANTS` на бэкенде); чем больше людей с видео и экраном, тем выше нагрузка на канал и процессор.

- Позже вошедший создаёт offer всем, кто уже в звонке; все сигналы группы идут с `to_user_id` (см. `call/CALLS.md` бэкенда).
- Приглашение показывает название чата и тех, кто уже в звонке. Отказ не завершает звонок для остальных.
- Пока идёт звонок, в чате висит баннер «Идёт звонок · Присоединиться» (событие `call_group_state` и `GET /call/api/active/`).
- Плитка участника: аватар или видео, значок выключенного микрофона, значок демонстрации экрана; клик по плитке увеличивает её,
  экран собеседника увеличивается автоматически. Мини-карточка и отдельное окно работают и для групп.
- Если соединение с одним участником пропало, плитка помечается «Нет связи», остальные продолжают разговор.
- После обрыва сокета клиент сверяет список участников с сервером и достраивает/закрывает соединения.
